# ADR 0002: 개발 중에는 Docker 를 쓰지 않는다

작성 2026-10-20 / 보완 2026-10-27

## 맥락
최종 산출물은 폐쇄망 설치가 가능한 형태여야 하므로 Docker 패키징이 필요하다.
그러나 개발 환경은 Windows 11 + RTX 3070 단일 PC 이고, 가용 기간은 1개월,
인원은 1명이다.

Windows 에서 컨테이너가 GPU 를 쓰려면 WSL2 + nvidia-container-toolkit 구성이
필요하다. 이 구성은 드라이버·WSL 커널·toolkit 버전 조합에 따라 실패하며,
실패 시 원인 분리에 하루 이상이 소모될 수 있다. 1개월 일정에서 이는
RAG 구현 자체를 위협한다.

## 결정
개발 기간 중에는 호스트에서 직접 실행한다(venv + Ollama 네이티브).
컨테이너화는 기능이 완성된 뒤 2026-11-14~16 에 일괄 수행한다.

### 패키징 단계의 두 안

**A안 (먼저 완성)** — FastAPI + Streamlit 만 컨테이너, Ollama 는 호스트
- 컨테이너가 GPU 를 몰라도 되므로 WSL2/toolkit 구성이 불필요
- `OLLAMA_BASE_URL` 을 `http://host.docker.internal:11434` 로 주입
- 예상 반나절. 실패 가능성 낮음

**B안 (시간이 남으면)** — Ollama 까지 컨테이너
- WSL2 + nvidia-container-toolkit 필요
- 예상 2~3일. 막힐 수 있음

A안만으로도 "애플리케이션 계층은 컨테이너, 추론 서버는 호스트"라는
구성은 폐쇄망에서 일반적이므로 결과물로서 결함이 아니다.

## 이 결정이 코드에 남기는 제약
개발 중 Docker 를 쓰지 않더라도, 나중에 컨테이너에 넣을 수 있는 형태는
지금부터 유지한다.

- 호스트·포트·모델명을 코드에 하드코딩하지 않는다 → `app/config.py` 가
  `.env` 에서 읽는다. A안에서 `OLLAMA_BASE_URL` 만 바꿔 끼우면 된다.
- 경로는 `__file__` 기준 절대경로로 계산한다. cwd 에 의존하면
  컨테이너의 WORKDIR 에서 깨진다.
- `sys.path.insert` 같은 import 경로 조작은 패키징 시점에 제거한다
  (현재 `app/api/main.py` 에 남아 있음).

## 대안
- 처음부터 Docker: 환경 문제 디버깅에 일정을 소모할 위험이 커서 배제
- 끝까지 Docker 없음: 폐쇄망 설치 가능성을 보여주지 못하므로 배제

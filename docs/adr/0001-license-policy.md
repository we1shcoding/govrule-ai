# ADR 0001: 라이선스 정책 — 카피레프트 배제

작성 2026-10-20 / 보완 2026-10-27

## 맥락
본 프로젝트는 공공기관 폐쇄망 배포를 가정한다. 기관이 소스 공개 의무를
부담하지 않도록, 전염성(copyleft) 조항이 있는 의존성을 배제해야 한다.
또한 포트폴리오로서 "왜 이 라이브러리를 안 썼는가"를 설명할 수 있어야 한다.

## 결정
직접 의존성(requirements.txt)은 MIT / Apache-2.0 / BSD / PSF 계열만 사용한다.
GPL, LGPL, AGPL, SSPL 계열은 기능이 우수하더라도 채택하지 않는다.
전체 목록과 각 패키지의 라이선스는 LICENSES.md 에 기록한다.

## 배제한 것과 대체 수단

| 기술 | 라이선스 | 대체 |
|---|---|---|
| Kiwi / kiwipiepy | LGPL v3 | BM25 직접 구현 |
| PyMuPDF | AGPL-3.0 | 법제처 API 가 텍스트를 제공하므로 불필요 |
| OpenAI / Claude API | (라이선스 아님) | 온프레미스 요구사항에 위배 |

LGPL 은 동적 링크 시 공개 의무가 발생하지 않는다는 해석이 일반적이나,
파이썬 패키지의 링크 형태는 해석의 여지가 있고 기관 법무 검토에서
설명 비용이 발생한다. 형태소 분석기는 BM25 품질에 영향을 주지만,
법령 텍스트는 한자어 명사 위주라 음절/어절 기반 토크나이징으로도
실용적 수준이 나온다고 판단했다. 색인 구축 후 실측한다.

## 예외: certifi (MPL-2.0)

requests 의 전이 의존성인 certifi 는 MPL-2.0 으로, 위 정책 범위 밖이다.
의도적으로 유지하며, 근거는 다음과 같다.

- MPL-2.0 은 **파일 단위** 카피레프트다. 해당 파일을 수정해 배포할 때만
  그 파일의 소스 공개 의무가 발생한다.
- 본 프로젝트는 certifi 를 수정하지 않고 CA 번들을 읽기만 한다.
  따라서 프로젝트 코드로 의무가 전파되지 않는다.
- 제거하려면 requests 를 버리고 표준 라이브러리 http.client 로 내려가야 하며,
  이는 실익 대비 비용이 크다.

**따라서 "카피레프트 0건"이 아니라 "전염성 카피레프트 0건, 파일 단위
카피레프트 1건(비수정 사용)"이 정확한 표현이다.** README 및 LICENSES.md 의
서술을 이 기준으로 맞춘다.

## 검토 절차
새 패키지 추가 시 `pip-licenses` 로 확인 후 LICENSES.md 를 갱신한다.
전이 의존성까지 확인하며, 정책 밖 라이선스가 나오면 본 ADR 에 예외로
기록하거나 패키지를 교체한다.
